## Context
当前报告使用 issues/new 的有界 URL，只携带诊断；Quick Look 通过受控交接进入主 App。完整文档不能塞进诊断字段或 URL。复现包是用户主动选择分享的内容，须与自动安全诊断分开。

## Decisions
- 首版使用 GitHub 原生 ZIP 附件，无新增文件托管服务。GitHub 网页上传会立即传输文件，不应提示为“提交 Issue 后才上传”。官方说明：https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files
- 原入口保持快捷报告；可选材料入口提供“不附内容 / 失败片段 / 完整文档”。完整文档未经选择不读取入包，相关图片资源单独选择。
- 快照绑定 incident 和文档 generation；若原失败快照不可用，允许用户选择当前文件，但明确标记为报告时版本，不能冒充发生错误时内容。无保存路径的文档可导出当前内存快照。
- 数学细类使用 syntax/output/unresolved-reference/input-limit/unsupported-resource 等固定枚举，不传原始异常。片段使用独立可选通道，不放进通用 errorFeedback 的任意字符串字段。
- ZIP 使用中性内部名 document.md、sample.md、diagnostics.txt、manifest.json；文件名改写不代表内容已脱敏。必要时重写所选资源引用并保留相对布局，不改变用户原文档。
- 不扫描目录；仅选入明确引用且获准读取的本地资源。不抓取远程资源、不打包越界或符号链接目标；缺失项列在清单，用户可继续分享已有内容。
- 初始预算：最多 100 个文件、源码/资源合计 20 MB、ZIP 小于 25 MB；超限展示具体项，允许取消资源或仅分享片段，不静默截断原文。预算须在读取、压缩和导出时执行。
- 压缩完成后展示可检查/移除的材料与拖动附件；GitHub 页面附上 ZIP 后用户提交。未获得服务回执，App 仅显示“已准备/已打开 GitHub”，不自行宣称附件已上传。
- Quick Look 受限环境先展示有界片段，经用户继续后沿既有受控交接传入主 App；完整文件在宿主由用户选择并标注报告时版本。遵守现有权限，不接受 renderer 提供的任意本地路径，大文件不通过现有 16 KiB incident payload 传递。
- 取消、失败与重试保留当前报告；仅在保存时创建 0700 临时工作目录，完成或失败后立即删除；用户主动保存的 ZIP 不自动删除。窗口内草稿保留以便重试，应用退出结束；崩溃后的残留扫描作为未实现边界记录。

## Risks / Trade-offs
- 网页附件需要用户完成一次拖放/选择；首版不承诺自动上传。
- 全文、图片、文件内容及元数据都可能泄露信息；提示明确分享范围并允许检查，不能声称自动脱敏或替用户判定敏感性。
- 失败依赖整篇上下文时，片段可能不足；完整文档选项和缺失资源清单必须可见。

## Issue 关联与新回复提醒
- 为每次本地报告保留稳定标识。打开 GitHub 页面仅表示开始提交；通过官方 API 回读实际存在的 Issue、匹配正文中的完整 Incident ID 才自动关联，不能按标题/时间推断提交成功。使用有界、可分页的仓库 Issue 查询；搜索索引延迟不能作为唯一发现途径。若无法唯一匹配或用户删除标识，保留待关联状态并提供粘贴 Issue 链接的补救，独立回读验证仓库/类型/存在性，不能把其他人的报告静默认领。
- 初次自动发现时，以提交 Issue 的时间作为评论基线，立即检查已发生的回复，避免关联延迟吞掉第一条答复。用户主动关联旧 Issue 时展示历史及明确基线。
- 首版主 App 启动、回前台及运行期间周期检查；初始周期 5 分钟，加抖动。尊重 ETag、分页、Retry-After、GitHub rate-limit 和失败退避，保存成功同步游标，单次失败不推进它。退出期间没有实时推送承诺，下次运行补查。此项会在用户选择反馈跟踪时说明。
- 评论使用官方 API 的稳定 ID 与 html_url，跟踪已知 Issue 的新评论；作者为 Issue 报告者本人时不产生“他人回复”提醒，维护者、普通参与者及机器人回复均可提醒。新评论从旧到新排列，不把单纯 updated_at 改变或 Issue 关闭当作新回复。
- 本地持久化两个独立进度：已同步评论和用户已点击处理的评论。同步、系统通知展示/关闭、切换窗口、清理缓存或 App 重启都不能推进用户处理进度。
- 提供“我的反馈”入口及明确未读数量/标记。可选系统通知按 Issue 合并，系统权限拒绝不影响应用内提示；Quick Look 至少有可进入宿主“我的反馈”的入口，不能以用户只用 Quick Look 为由藏起全部提醒。
- 每项提醒固定到具体新评论。用户点击提醒后打开经过固定仓库校验的评论 html_url（#issuecomment-ID）。仅浏览器接受打开成功后，清除此条及该次点击明确覆盖的提醒；打开失败保留标记并提供重试/复制链接。该状态仅代表用户点击打开，不声称网页加载成功或实际读完。
- 多条回复时，打开该 Issue 的首条未读评论；保留之后未点击覆盖的评论提示。一次点击期间新到的评论始终保持未读，不能用“最新时间”整体清零。
- 关闭系统横幅不是点击消息，不清除应用内标记。通知被系统移除后仍可从 App 找回。Issue 已关闭不清理未读，已删除评论显示不可用并需用户主动处理该项；网络失败不作为删除证据。
- 官方评论 API：https://docs.github.com/en/rest/issues/comments 。客户端不内置维护者 Token，不依赖用户开启 GitHub 邮件；仅跟踪明确关联的公开 Issue，不要求读取用户其他仓库或通知。
