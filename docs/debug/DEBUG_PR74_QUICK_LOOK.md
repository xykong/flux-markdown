# PR #74 Quick Look 集成验证

审查基线为外部贡献 `be4829f`，集成基线为 master `b5b2ece`。

- 文件刷新用文件版本识别变化。验收条件是同一 inode 原地改写前文后追加，普通预览及 Follow 都显示实际内容，文件未变时不重复读正文。
- Markdown 全窗口按原有语义解析。验收条件是跨行引用定义可跨越原分段边界生效，逐批提交 DOM 后最终输出与一次提交一致。
- 恢复按钮根据预览模式和大小选择。验收条件是仅在 Follow 可用时显示该操作，紧凑预览仍可在支持的大小范围内打开主应用，超限文件可在 Finder 中定位。

## 集成调整

- 文件改写和追加通过重新读取窗口验证。常规刷新只在文件版本变化时读正文。尾窗要保留文件行号，文件变化后仍需扫描之前的内容，长时间和超大文件的运行开销待验收。
- 去掉按源文本分段解析的路径，保留按 DOM 批次显示的路径。现有链接引用、缩写或脚注定义会触发完整渲染，覆盖追加内容扩展既有引用定义的情况。
- 截断提示根据大小和模式路由，覆盖六种语言。Finder 紧凑和展开模式的实际点击、VoiceOver、Intel 尚未验证。

## 当前证据

- 原提交复现：前部原地改写后追加仍显示旧前文。分段模式下跨行引用在主应用、展开和紧凑 Quick Look 中失效。
- 集成候选的真实 WebKit 严格性能探针中，2 MiB 文档首次文本为 394 ms，最长主线程间隔为 379 ms，超过 300 / 200 ms 目标。保留该性能门槛。
- 本机 Xcode 27.2 的 SDK 最低部署目标为 12.0。原生本地编译和测试用命令行覆盖值，项目的 11.0 设置不改。一次全量测试运行停在跨文件阅读测试触发的现有模态弹窗。
- 最终 renderer Jest 为 717 个通过，生产 bundle 构建通过。OpenSpec 两项变更通过严格校验。窗口读取修复包含快速文件替换和窗口前方行数变化的原生回归用例。
- 后台 WebKit 重测中，2 MiB 试件首次文本 417 ms、最长间隔 404 ms，全窗 795 ms，首批也未达到原测试要求的总耗时一半以内。此项仍阻止合入。

## 合并候选

- 采用整窗 Markdown 解析、缩小 emoji 匹配范围以及按完整块分批净化和显示。2 MiB 密集日志在 M5 Max 的后台 WKWebView 复测中，首批正文进入 DOM 从 615 ms 降到 185 ms，整窗完成从 1,235 ms 降到 987 ms。三轮对照的最终 DOM 指纹一致。
- 维护者接受当前性能结果用于合并，原 Finder 可见绘制与 200 ms 卡顿目标仍待单独验证。含跨块 HTML 和超长连续文本保留现有完整渲染路径。

## 正式版验收

- `v1.57.885` 的 Finder 实测确认 2 MiB 文档完整渲染，超限时才显示紧凑通知。开启跟随后可见原尾段和追加内容，关闭后恢复开头和超限提示。
- 正式包的 2 MiB 后台 WebKit 首批正文中位数为 137 ms，主线程间隔最高 140 ms。Finder 自动按空格后，首次采到正文的帧落在 642–762 ms 区间。各指标的采样口径、平台和分发结果见 [v1.57.885 发布记录](../release/RELEASE_1.57.885.md)。
