# 错误区域的紧凑反馈入口

用户本地验收指出错误区域同时展示提示、五个按钮和披露说明，选择负担过大。按用户明确要求调整为右上角红色“! 反馈”单入口；点击后才展示原有恢复、诊断检查、复现材料、我的反馈及 GitHub 说明。此验收纠正取代此前的常驻一键 GitHub 入口布局，不更改报告的权限和提交确认。

验收指标：关闭时只有一个可见反馈入口；点击不直接外发或打开 GitHub；展开后原有动作可用；Escape/再次点击可收起；键盘焦点可达；旧代次不能触发动作；图片恢复移除入口；源码与复制/搜索/导出不包含反馈控件。修改仅应用于 renderer 的文档错误区域，保留原生渲染器失效时的后备能力。

## 实现与验证

- 错误区域使用相对定位包装，唯一常驻控件为右上角红色“! 反馈”；原有说明和操作放入默认隐藏的非模态面板。
- 点击只展开界面，不调用报告/上传桥；再次点击、Escape 或焦点离开收起，Escape 返回入口焦点。一次只展开一个区域。
- 区分固定错误分类、源码范围、代次和 incident 的原逻辑保留；嵌套数学错误只显示一个入口，图片恢复后移除包装。
- 复制/搜索忽略控件；HTML 导出移除控件并解包，保留原错误节点。深浅主题和六种界面语言保留。
- Jest 全量 67 suites / 623 tests 通过；TypeScript、Vite 和 Release 本地构建通过。
- 真实 WKWebView 的 compact mathematical feedback entry 验证右上角几何、关闭状态按钮不可见、材料操作存在、Escape 和导出 DOM 清理；现有 contextual feedback bridge 验证事件隐私和旧代次拦截。
- 这次调整不更改原生渲染器失效后备界面，不扩大现有真实 GitHub 上传/系统通知的验收结论。
