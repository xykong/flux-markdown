# 自动预填反馈与默认附带当前文档

用户验收指出：改为原生对话框后，补充说明编辑框为空，且当前文档没有默认附带。本次按用户明确要求恢复可见的自动问题摘要，并在反馈对话框中默认选中出错时的完整文档快照；用户可检查、替换或取消。GitHub 仍需用户确认，默认准备附件不代表后台上传。

验收指标：首次打开摘要非空、含操作/失败分类/版本；不覆盖用户编辑；主 App 与 Quick Look 都绑定本次 incident 的快照；默认附件可见且可排除；准备失败不能默默按“已附带”继续；不将全文塞入 URL；网络传输/上传必须在明确操作后发生。Quick Look 大文档走签名校验的 XPC + 私有一次性交接，而不是扩大诊断 URL。

## 实现

- `IncidentDraft.prepareDefaultContent` 生成可编辑的可见摘要：问题、来源、操作、失败分类、应用版本。只在首次准备时填充，不覆盖之后的编辑或主动清空。
- 原生对话框默认勾选“附带当前文档”，自动用该 incident 的渲染输入快照生成 ZIP。文件名/准备状态始终可见，支持查看或更换文件及取消附件。诊断排除会重新生成包；准备期间的替换/编辑采用快照和完成回读，旧任务不会覆盖新选择，取消窗口不继续导航。
- 点击继续时确保附件准备成功；失败保留报告，要求选择文档或明确取消附件。成功后定位 ZIP 并打开预填 GitHub 页面，用户将 ZIP 拖入网页后上传，再确认发布。不声称打开页面即已上传。
- 缓存目录为私有临时目录，0700 目录/0600 ZIP，按 incident 复用，后续准备时清理超过 24 小时的应用生成缓存；不清理用户主动保存的 ZIP。
- Quick Look 从原生渲染上下文取得完整快照，通过新增受信任 peer 的 `reportDocumentError` XPC 方法交给固定宿主 launcher。小型诊断 URL 只携带一次性随机 token；正文不进入 URL。
- launcher 新增且仅新增 `FeedbackTransfers/` 的沙箱写入范围；现有签名、同用户和固定扩展路径校验不变。传输 JSON 最大 32 MiB、文档 20 MiB、片段 6000 字节，最多 10 个未消费文件；一小时过期清理，宿主成功/失败解码后消费该 token。私有文件为 0600；拒绝符号链接、错误 owner/权限和非 review 请求。
- App 与 Quick Look 六种本地化均已补齐。高级复现编辑器有全文时也默认选中完整文档。
