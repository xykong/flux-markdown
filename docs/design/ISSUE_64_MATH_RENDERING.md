## 5. 技术选择

| 方案 | 优点 | 需要承担的问题 | 决策 |
| --- | --- | --- | --- |
| KaTeX + 补分隔符/围栏 | 改动小，现有快路径成熟 | label/ref 官方不支持，必须另写文档语义；难以覆盖 AMS 前向/多行编号 | 不作为完整目标的主方案 |
| KaTeX 优先、逐公式失败后 MathJax | 表面上兼顾性能 | label、宏、计数器跨公式共享；未报错的缺失引用不会触发 fallback，混排字体/编号不一致 | 不使用逐公式自动 fallback |
| 整份 TeX 文档统一用 MathJax 4 | 原生支持编号、前向引用及 MathML；语义集中 | 启动/内存、离线切片、可访问性、输出清理和导出须验证 | 推荐；先通过原生离线与性能门槛 |

推荐使用固定版本 MathJax 4 的模块化构建，正文 TeX 采用一个文档级引擎。首轮以 4.1.3 研究基线建立 lockfile；合入时核对官方版本与已知兼容性。已有 Typst 和 Mermaid 可能继续依赖 KaTeX，不连带删除依赖或改变其路线。

首选 SVG 输出，局部字体缓存，便于离线导出和避免外部字体引用；必须保留数学语义及源码复制通路。SVG 的可复制性和无障碍能力不能从“有矢量图”推断。与 CHTML 的包体、字体、布局和可访问性对比列入第一阶段，不允许靠隐藏辅助内容获得性能达标。

## 6. 实现结构

### 6.1 Markdown 与数学的边界

新增 `math-syntax.ts`：在 markdown-it token 阶段识别数学，优先评估维护中的 tokenizer 插件并逐条验证；无现成实现满足时才写小型规则，不写 TeX 解析器。

- 行内规则在 Markdown 反斜杠转义前识别 `\(`，与 `$` 共用确定的空白/转义/闭合规则；`$$` 优先于 `$`。仅消费完整数学 token，携带原文、起止行和 inline/display 类型。
- 块规则支持 `$$`、`\[` 和 `math` 围栏（反引号/波浪号及合法嵌套缩进）；未知或未闭合输入的消费边界必须有测试，不能吞正文。
- 代码跨度、普通/缩进/长围栏代码、HTML 属性、注释、URL、YAML、脚本示例不扫描。不能在全局字符串上做分隔符替换，或在已被 Markdown 改写的 DOM 中重新猜原始转义。
- 在列表、引用、脚注、强调、表格单元格和标题中测试数学；GFM 表格的转义竖线要无损传给公式，不能让数学处理改变普通表格分列规则。
- MathML 从清理后的展示型 DOM 收集，只处理有效允许的节点；不启用任意 XML 外部实体或 HTML 执行能力。
- 补充 AMS `equation/align/gather` 及星号形式、`\ref`/`\eqref`（数学内及普通段落）支持，限定识别边界；不把任意 `\begin{...}` 交给全文扫描。

token 输出惰性占位节点；原始 TeX 保存在当前 render 的内存映射中，避免把源码拼进可执行属性。根据 token 是否存在加载数学模块，替换目前美元正则触发机制。

### 6.2 文档级排版、编号和状态

新增 `math-renderer.ts`，提供 `renderMathDocument(tokens, root, generation)` 和 `dispose()`：

1. 每次文档渲染建立独立 TeX/MathDocument 状态；只复用不可变模块和可安全共享的字体资源。处理宏、标签、计数器、错误与临时 DOM 的释放。
2. 所有数学项按源文档顺序交同一文档处理，使用支持引用重处理的文档 API；不逐式 `tex2svg()` 后假设前向引用自然正确，也不随滚动顺序改变编号。
3. 默认 `tags: 'ams'`：普通 `$$`/`\[` 不自动编号；AMS 非星号环境按其规则编号；`\tag`/`\tag*`、`\notag`/`\nonumber` 采用明确语义。补充测试不能隐式给原有全部公式加号。
4. `\label` 是文档内唯一标识；前向和后向 `\ref`/`\eqref` 可解。重复标签显示局部诊断、不覆盖首个有效目标；缺失/无编号/失败目标明确未解析，不能留下可点击的 `#` 或伪成功值。
5. 独立公式 ID 命名空间，稳定编码 label，并避免与标题、脚注、用户 HTML ID、SVG glyph ID 冲突；URI 编码后的标签准确解析。不要只改 SVG 的 id 而遗漏 use/href。
6. 完成后检查引用文本、实际目标与目标有效性。适配浏览器 `data-mjx-href` 为标准 fragment 链接、可聚焦节点和可读名称，接入现有导航；导出保留相同引用关系。
7. 受限的文档宏通过引擎配置处理，宏状态不能跨文件泄漏；允许包清单固定。禁用运行时任意 `\require`、自动远程包和 texhtml；未知命令必须进入错误流程，不能仅用 noundefined 染红冒充成功。

异步任务必须校验现有 render generation；过期任务不能写入新文档。避免在两个 await 间同时操作共享可变 MathDocument；切换源码、关数学、换文件和关闭 WebView 均清理。一次失败不得阻断后续有效公式。

### 6.3 输出、离线与可访问性

- 模块、SVG 字形数据、字体、语音/语义数据（若启用）全部打包到现有本地 scheme；静态列出最终运行时依赖。V4 的字体分片即使 SVG 输出也可能异步加载。
- 优先显式装配所需组件，验证内嵌 Worker 的本地加载。若选择静态辅助 MathML而非完整语音 Worker，必须经过真实 VoiceOver 验收并说明能力，不以关闭无障碍作为最终修复。
- 在 `safe-html.ts` 内扩展统一的数学输出策略，配合引擎 safe 配置，保留必要 MathML/SVG/ARIA、局部 use 和引用，拒绝主动内容与外部 glyph。不要直接把 MathJax 结果绕过清理塞入页面，也不要照搬会剥掉 `mjx-*`、样式/链接的默认清理后宣称正常。
- 当前测试页面为研究 CSP。生产只开放被选组件确实需要的 app 生成 Worker/data 字体能力，用户内容仍无脚本权限。
- SVG 继承主题色；数学 LTR 且与 RTL 正文隔离；窄窗口使用局部滚动或可靠换行，公式和编号不相互遮挡，不扩张整页。
- 切换字号、缩放和窗口宽度时重测排版，保证中文 text 的字体回退；搜索忽略隐藏辅助树产生的重复文字，公式源码复制能返回原始 TeX。

### 6.4 生命周期、设置、错误和导出接入

- `renderMarkdown` 的完成承诺必须包含数学排版、引用重处理和资源就绪；保留可显示的基础正文并提供有界加载状态。
- 保持 `enableKatex` 持久化键兼容，内部可映射为数学开关；六种界面语言将用户可见名称改为数学公式，避免显示与实际引擎不符。关闭时不加载引擎、TeX 源码可读，既有展示型 MathML 清理/显示策略明示且不意外改变。
- `error-feedback.ts` 接入新的数学错误类别/selector；复用 `ErrorIncident`/`ErrorFeedback`，保留源码和有效正文，提供编辑器/宿主恢复及一次操作的上下文反馈。诊断只含允许的元数据，不上传公式内容。更新 `DEBUG_ERROR_FEEDBACK.md` 覆盖清单。
- `waitForRenderComplete` / `waitForExportReady` 等待数学字体/引用；数学仍在处理或未解析时不得报告完整成功。无效语料的导出要明确失败及可恢复原因；以后若提供“含错误导出”，必须作为明确产品行为。
- HTML 导出为无数学运行时脚本也能显示/跳转的自足文档，包含必要样式、SVG defs 和辅助语义，无 `flux-renderer://` 依赖。
- PDF/打印验证公式、编号与分页完整；必须声明并验证 PDF 链接能力，不能由 HTML 链接可用推断 PDF 有可点击目标。App/CLI 的导出等待路径保持一致。

## 7. 独立验收方法

### 原始材料与裁判

1. issue 原文、原 zip、固定提交的建议页面、原始文件 hash 是输入裁判。
2. 人工审定的逐项期望清单是需求裁判：明确公式数量、结构、编号 `(1)`、引用目标、保留的货币/代码和预期错误。不可从新实现自动生成这些期望。
3. LuaLaTeX + amsmath（含必要中文支持）编译同一 TeX 语料，至少两遍并检查 `.aux`/日志，作为独立的编号/引用和排版参照；固定 TeX 环境/包版本。本机本次未安装，尚未执行。
4. 同语法子集用 KaTeX 做差分；MathML 的数学结构按 W3C MathML Core及原始结构核对。MathJax 对 MathJax 的比较只能检验接入，不能独立证明语义正确。
5. 字体、换行和抗锯齿不同，不要求两个引擎逐像素相同；比较符号、上下标、行列数、界限、标签和关系，再由独立人工检查可读性。

| 层 | 工具/方法 | 必须证明 |
| --- | --- | --- |
| 词法与保护 | Jest、固定原文、性质/变形测试 | token 源范围正确；代码、转义货币、普通括号/孤立美元不变 |
| 语义与引用 | 真实 MathJax、手写期望、LaTeX `.aux`、MathML 树 | 11+1 成功、1 预期错误；值与目标正确，前向/重复/缺失有确定结果 |
| 输出清理 | 生产 sanitizer 前后语义/链接/defs 对比 | 安全过滤有效，同时没有丢 glyph、标签、ARIA 或引用 |
| 真实浏览器接入 | `Tests/RendererIntegration` + 本地 scheme | 动态模块/字体/Worker 实际加载；零远程依赖，最新 generation 生效 |
| 产品宿主 | App、真实 Finder 预览栏与 QuickLook | 进程复用、关闭重开、快速切文件、设置迁移、快捷键、沙箱 |
| 视觉和交互 | 截图、几何断言、键盘、VoiceOver | 无裁切/重叠/缺字；编号对齐，引用可达，辅助语义不重复读 |
| 导出 | 实际 CLI/App 导出，离线打开 HTML，PDF 渲染成图 | 等待完整、无运行时资产依赖、无缺页/断公式；明确链接能力 |
| 回归/性能 | 原整份附件、已有 fixture、重复冷暖实验 | 基础 Markdown、图表/Typst 和无公式快路径不退化 |

上下文覆盖：App/QuickLook/Finder × 明暗主题；宽度至少 320/600/1200 CSS px；正常及 200% 缩放；中文、英文及 RTL 正文；最老受支持 macOS/WebKit 和当前版本。核心公式/引用在全部宿主跑，次要组合可用成对覆盖，避免只跑一个大笛卡尔积却遗漏实际宿主。

额外边界：前后向引用、同名 label 跨文件、删除/移动公式、同一文档重渲染、空文件后重开、Unicode/标点标签、失败公式被引用；宏跨文件隔离；MathML/TeX 混排；GFM 表格竖线；HTML 实体、小于号、代码中数学标记；未闭合/超长/递归宏、资产缺失、过期任务及超时。随机测试必须记录 seed 和最小化反例。

用变形验证发现状态错误：重渲染相同文档结果不变；把标签和引用一致重命名不改变公式值；插入无关段落不改变显式编号；把公式前后移动后引用仍指向相同 label；切 A→B→A 与新建独立视图的结果相同。

用故障注入检验测试是否有用：故意删引用目标、换错编号、删 SVG defs/字体、漏 await、保留旧 generation、禁用必要资产，测试必须失败。不得以“DOM 非空”“无 JS throw”“有一个 SVG”作为成功标准。

性能门槛先测基线后锁定：固定硬件、macOS、输入、viewport、cache 状态，冷启动至少 20 次，暖态预热 5 次后测 30 次，记录 p50/p95、主线程长任务、RSS、资产字节和有效项数。无公式文档不得加载数学 JS/字体；建议无公式 p95 回归不超过 max(10%, 10ms)。100/1000 公式语料分别设定有限资源与完成时间预算；在阶段一写入实测绝对门槛并冻结，不把本次单次原型用时当基准。

## 8. 实施顺序与交付

1. 固定语料/手写期望/独立 LaTeX 参照；完成 MathJax SVG 与 CHTML 在真实本地 scheme、旧系统、可访问性和性能方面的选择验证。
2. 测试先行加入 token 支持与保护规则，明确触发/关闭行为。
3. 接文档级 MathJax、编号引用、隔离与错误映射；完成输出清理和标准链接适配。
4. 集成设置、多语言、源码/搜索/目录、RTL、导出等待与自足输出。
5. 跑独立验收矩阵、故障注入和回归；形成可重复证据报告、回退策略与发布说明。

每项独立验证完成后按仓库规则提交 Conventional Commit。当前仅交付研究、设计和 OpenSpec 提案；实际产品实现按提案评审流程开始。发布和 issue 回复需要进入单独已授权的发布流程。
